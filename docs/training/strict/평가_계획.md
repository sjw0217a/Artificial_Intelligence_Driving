# 보조 규칙을 뺀 모델(strict): 학습·평가 계획

결과를 보기 전에 정해 둔 규칙이다. 결과를 본 뒤에 이 규칙을 바꾸지 않는다. 바꿔야 하면 바꾼 이유와 시각을 이 문서 끝에 적는다.

## 1. 왜 다시 만드나

교수님 Q&A에 따르면 보조 규칙이나 도움을 주는 요소를 넣으면 안 되고, 라우팅은 지도 수준만 허용된다(어떤 차선으로 갈지 같은 세밀한 정보는 금지). 이 기준에 맞춰 예전 최종 모델(v3_3)의 환경에서 네 가지를 바꿨다.

| 항목 | 예전 (v3_3) | 지금 (strict) | 이유 |
|---|---|---|---|
| ego `speed_mode` | 24: 적신호 정지·교차로 우선권을 SUMO가 대신 함 | 0: SUMO 보조 없음 (수업 원본과 같음) | 보조 규칙 금지 |
| 관측 [35] | 목표 차로까지 칸 수 | [35] 다음 회전 방향, [36] 회전 지점까지 거리 (내비 수준) | 차선 단위 안내 금지, 지도 수준 라우팅 허용 |
| 관측 [33]·[34] | 옆 차로 훑기 + SUMO 차선변경 판정(`couldChangeLane`) | 측면 레이더: ego 옆 띠 안 차의 위치·속도로만 판정 | SUMO 규칙의 판단 결과를 관측으로 주지 않음 |
| ego 시작 차로 | `best`: SUMO가 경로에 맞는 차로를 골라 줌 | `random`: 진입 도로 2차로 중 무작위 | 경로 정보로 자리를 잡아 주지 않음 |
| 교차로 안 충돌 검사 | 꺼짐 (SUMO 기본값) | 켬 (`--collision.check-junctions true`) | ego가 교차로에서 스스로 양보해야 하므로, 교차로 안 충돌을 빠짐없이 센다 |

관측은 38차원이 된다: [0..30] 수업 기본, [31] 신호 상태, [32] 정지선 거리, [33]·[34] 측면 레이더, [35] 다음 회전 방향, [36] 회전까지 거리, [37] 정류장 버스 정차.

선생(규칙, `utils/rule_policy.py`)은 학습 정답을 만들 때만 쓴다. SUMO 내부 정보를 읽지만 주행에는 끼어들지 않는다. 주행은 신경망이 관측만 보고 한다. 선생은 이제 적·황신호에 스스로 선다(관측 [31]·[32]만 사용).

## 2. 만드는 모델 세 개 (같은 BC에서 출발)

| 모델 | 만드는 법 | 평가에 쓰는 파일 |
|---|---|---|
| BC | 선생 시연 1,000 Episode(평시 400, 크리스마스 400, 크리스마스·버스 3배 200)를 지도학습 | `results/strict_0/pretrained_model.pt` |
| BC + DAgger | BC 모델이 운전, 선생이 정답. 3라운드, 라운드당 400 Episode, β = 0, 데이터 누적, 라운드마다 처음부터 학습 | `results/strict_3/pretrained_model.pt` (마지막 라운드) |
| BC + PPO | BC 모델에서 PPO 미세조정. 예전 PPO B 설정(학습률 5e-5, 40만 step, 평시·크리스마스 섞기, 버스 3배, BC 정규화 0.1)과 같다. BC 정규화 데이터는 선생 시연만 | `results/strict_ppo/model.pt` (마지막 모델) |

- 학습 설정(학습률, 배치, epoch, 시드 0)은 예전 최종 모델과 같다. 스크립트: `scripts/training/train_strict_model.sh`, `scripts/training/train_strict_ppo.sh`.
- 수집 시드: 시연 141~143, DAgger 151~153·161~163·171~173. 예전에 쓴 시드와 겹치지 않는다.
- PPO 보상에는 신호 위반 벌점(−5, 충돌과 같은 크기)이 있다. BC와 DAgger는 보상을 쓰지 않는다.
- 평가 파일은 위 표대로 미리 정했다. PPO 학습 중 내부 평가로 고른 best 모델은 쓰지 않는다.

## 3-1. 최종 모델 고르는 규칙 (결과를 보기 전에 정함)

1. 검증 시드(441101~441112, 조건마다 300 Episode)로 후보를 모두 평가한다.
2. 충돌률 5% 미만이고 신호 위반 Episode 1% 이하인 후보만 남긴다.
3. 그중 실패(충돌·신호 위반·경로 이탈·시간초과) Episode 합계가 가장 적은 것을 고른다.
4. 실패 합계 차이가 6회(1,200 Episode의 0.5%p) 이하이면 복잡 구간 평균 시간이 더 짧은 것을 고른다.
5. 고른 뒤에 최종 평가 시드로 후보 전부를 한 번 평가해 보고한다. 최종 평가 결과를 보고 고른 모델을 바꾸지 않는다.

- 시간초과: Episode는 최대 600 step(300초). 그 안에 도착하지 못하면 시간초과이고 실패로 센다 (수업 기준 "무한정 대기 없음").
- DAgger는 β = 0 하나만 후보로 둔다. β를 바꾼 것은 후보가 아니라 시간이 남으면 참고 비교로만 돌린다.
- PPO는 첫 시도를 포함해 최대 3번까지 설정을 바꿔 볼 수 있다. 바꿀 때는 검증 시드 결과만 본다. 시도한 설정과 결과는 모두 변경 기록에 남기고, 그중 검증 결과가 가장 좋은 하나만 후보로 올린다.

최종 평가 시드 배정: 평시 21~23, 크리스마스 24~26, 크리스마스 ×1.3 27~29, 크리스마스·버스 3배 30~32 (앞에 20261117을 붙인다). 조건마다 시드 3개 × 100 Episode. 세 모델이 같은 시드를 쓰므로 Episode마다 교통이 같다.

## 4. 지표 (미리 정함)

- **충돌률**: 충돌한 Episode 수 / 전체. 수업 기준 5% 미만.
- **신호 위반**: 정지선을 넘은 0.5초 스텝의 앞뒤 모두 적신호(r, R, u)였던 횟수와, 한 번이라도 위반한 Episode 수. 스텝 사이에 신호가 바뀐 경우는 언제 넘었는지 알 수 없어 세지 않는다 (세 모델에 똑같이 적용). 정지선 앞에서 차로만 바꾼 것은 통과로 보지 않는다.
- **경로 이탈률, 시간초과율**
- **성공**: 충돌·경로 이탈·시간초과 없이 도착하고 신호 위반도 없는 Episode.
- **복잡 구간 통과시간**(S1 진입 → W_out 진입): 성공한 Episode 평균. 모델 간 비교는 두 모델 모두 성공한 같은 Episode끼리 뺀 차이의 평균과 95% 구간.
- 1,200 Episode에서 충돌 몇 번 차이는 통계적으로 구분되지 않을 수 있다. 그런 경우 "차이 없음"으로 쓴다.

## 4-1. expert(규칙) 점검 기준 (학습 전에, 개발 시드 441021~441028로 확인)

학생은 expert를 따라 배우므로 expert가 먼저 잘 달려야 한다. 조건마다 100 Episode(시드 2개 x 50)로 아래를 모두 넘어야 학습을 시작한다.

| 지표 | 기준 (조건마다) | 이유 |
|---|---|---|
| 충돌 | 2% 이하 | 수업 기준 5%보다 충분히 낮아야, 학생이 조금 나빠져도 기준 안에 든다 |
| 신호 위반 Episode | 1% 이하 | 신호를 지키는 것을 학생이 배울 수 있어야 한다 |
| 경로 이탈 + 시간초과 | 3% 이하 | 목적지 완주 |

못 넘으면 개발 시드에서 원인을 찾아 expert만 고치고, 고친 내용을 변경 기록에 적은 뒤 다시 점검한다.

## 5. 지키는 것

- 최종 평가 결과를 본 뒤에 모델, 설정, 지표를 바꾸지 않는다.
- 선생이나 환경을 고쳐야 하면 개발 시드에서만 확인하고, 고친 내용을 이 문서 끝에 적는다.
- 예전 최종 모델(v3_3)은 지우지 않고 비교·대비용으로 남긴다.

## 변경 기록

결과를 보기 전, 코드 검토에서 고친 것:
- 신호 위반 감지: 정지선 앞 차로 변경을 통과로 잘못 세던 버그 수정, 앞뒤 모두 적색일 때만 위반으로 정의.
- 교차로 안 충돌 검사를 켬 (위 표). 켜지 않으면 교차로 안 충돌이 빠져 성적이 실제보다 좋게 나온다.
- ego 시작 차로 `best` → `random` (위 표).
- 위 수정 전에 돌리던 선생 점검 두 번은 결과를 보기 전에 멈추고 버렸다.

검증 결과를 본 뒤 (3-1절에서 허용한 PPO 재시도):
- 검증 선정: BC + DAgger (기준을 넘은 후보가 이것 하나). 결과는 `val/selection.txt`.
- PPO 2차 시도 (`strict_ppo2`): 1차 학습 로그에서 찾은 결함 하나만 고친다. critic warmup 5번 동안
  가치 출력층만 바꾸게 함 (`--warmup-value-head-only`). 1차는 가치와 정책이 공유하는 앞단까지 바뀌어 정책이 흔들렸고
  (첫 업데이트 approx_kl 0.47, 학습 초반 내부 점검 충돌 10~30%), 그 동안 BC 정규화도 꺼져 있었다.
  다른 설정은 1차와 같다 (무엇이 효과를 냈는지 알 수 있게 한 번에 하나만 바꿈). 결과는 검증 시드로만 본다.
- PPO 2차 검증: 실패 73 (1차 102). 신호 위반 Episode 1.9%로 기준 탈락. 선정은 그대로 BC + DAgger.
- PPO 3차 시도 (`strict_ppo3`, 마지막): 2차 + 신호 위반을 학습 중에 충돌·경로 이탈처럼 즉시 종료(-5)로 다룸
  (`red_light_terminate=1`). 근거: 2차가 기준에서 떨어진 이유가 신호 위반 하나였다 (검증 결과). 평가에서는 종료하지 않고
  끝까지 달리며 위반을 센다 (1·2차와 같은 평가).
- PPO 후보는 1·2·3차 중 검증 실패 합계가 가장 적은 것 하나. 3차 검증 → 선정 → 최종 평가를 사람이 중간에 고르지 않도록
  `scripts/training/run_ppo3_and_final.sh` 한 번으로 돌린다.
- PPO 3차 검증: 실패 32 (충돌 1.5%, 신호 위반 Episode 13 = 1.1%로 기준 1% 이하에서 1회 초과 탈락). PPO 후보는
  1·2·3차 중 실패가 가장 적은 3차 (`val/ppo_candidate.txt`). 선정은 그대로 BC + DAgger (`val/selection_after_ppo3.txt`).

최종 평가 (시드 2026111721~32, 한 번만):
- 세 모델(BC, BC + DAgger, BC + PPO 3차) 각 1,200 Episode. 결과 `final_eval/summary.txt`.
  BC + DAgger: 충돌 1.6%, 신호 위반 0, 실패 20. BC + PPO: 충돌 2.1%, 신호 위반 0.8%, 실패 33. BC: 충돌 3.2%, 신호 위반 10.4%, 실패 155.
  최종 모델은 검증에서 고른 BC + DAgger 그대로다 (최종 평가 결과를 보고 바꾸지 않음).

최종 평가 뒤 정리 (모델·지표는 바꾸지 않음):
- expert를 검증 시드로 평가 (`scripts/training/strict_expert_val.sh`, 결과 `expert_val/`). 학생과 expert를 비교하는 참고용이고
  모델 선택에는 쓰지 않는다. 최종 평가 시드는 다시 쓰지 않았다.
- GitHub·노션에서 예전 환경(v3_3)의 기록과 모델을 내렸다. 5절 "예전 최종 모델은 지우지 않고 남긴다"는 개인 컴퓨터 보관으로 지킨다.
  학습 과정 기록 2~3절에 예전 환경에서 한 순서와 결론만 남겼다.
- BC + DAgger β 쿨다운(β = 0.5, 0.25, 0.125)을 참고 비교로 돌림 (2절 "β를 바꾼 것은 후보가 아니라 참고 비교로만"을 따름).
  β = 0과 같은 BC·수집 시드·Episode 수·학습 설정, β만 다름. 검증 시드로만 평가하고, 선정과 최종 평가 결과는 바꾸지 않는다.
- 새 모델로 재현성 확인(같은 데이터, 학습 시드 1·2, 검증 시드 평가)과 센서 오차 실험(새 시드 442001~3, 442011~3)을 추가.
  둘 다 최종 모델을 고른 뒤의 분석이라 선정과 최종 평가 결과는 바꾸지 않는다. 최종 평가 시드는 다시 쓰지 않는다.
- β 쿨다운 검증 결과 (참고): 충돌 16, 신호 위반 Episode 1, 실패 17, 복잡 구간 20.46초 (β = 0: 실패 23, 20.65초). 같은 Episode 짝 비교에서
  통계적 차이 없음 (p = 0.35, 시간 −0.21 ±0.26초). 후보였다면 규칙상 β 쿨다운이 선정됐겠지만, 참고 비교로 정해 두었으므로 최종 모델은 β = 0 그대로.
