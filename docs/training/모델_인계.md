# 학습 모델 인계 (AV 학습 → 데이터 수집)

- 최종 모델: **`models/bc_v3_3.pt`** (관측 37차원)
- 학습 과정 전체: [학습_과정_기록.md](학습_과정_기록.md), 팀 노션 "2. AV 모델 학습"

## 1. 파일

| 파일 | 내용 |
|---|---|
| **`models/bc_v3_3.pt`** | **최종 모델.** 버스 추월을 배운 BC + DAgger 3라운드 (37차원) |
| `models/bc_dag3_36dim.pt` | 이전 모델. 버스 추월 없음, 비교용 (36차원). 실행할 때 `BUS_STOP_FLAG=0`을 붙인다 |
| `utils/rule_policy.py` | 규칙 기반 운전자 (시연자, DAgger 정답) |
| `utils/pretrain.py` | PPO 네트워크를 시연 데이터로 지도학습 (BC) |
| `eval_section_time.py` | 복잡 구간(S1~S2) 통과시간, 버스 추월 횟수 평가 |
| `scripts/training/` | 최종 모델 학습, 공식 평가, PPO 추월 실험을 다시 돌리는 스크립트 |
| `docs/training/official_eval/` | 공식 평가 원본 결과 (Episode별 JSON) |

**관측이 37차원이다.** 이 브랜치 이전 코드(33차원)로는 모델이 돌아가지 않는다.

## 2. 성능

### 2.1 공식 수치 (새 시드로 딱 한 번 평가, 조건마다 300 Episode)

- 최종 모델을 정한 뒤 11/12에 한 번만 실행했다. 시드는 2026111201~12 (시드 3개 × 100 Episode).
- 이 결과를 본 뒤로는 모델을 바꾸지 않았다.

| 조건 | 충돌 | 경로 이탈 | 복잡 구간 통과시간 (평균 ± 95% 구간) | 중앙값 | 전체 도착시간 |
|---|---|---|---|---|---|
| 평시 | 0/300 | 0 | 15.2 ± 0.3초 | 14.0초 | 187.4초 |
| 크리스마스 | 0/300 | 1 | 21.3 ± 1.0초 | 17.5초 | 195.4초 |
| 크리스마스 + 교통량 1.3배 (처음 보는 조건) | 0/300 | 3 | 23.4 ± 1.1초 | 20.5초 | 199.8초 |
| 크리스마스 + 버스 3배 (스트레스 테스트) | 1/300 (0.3%) | 1 | 22.7 ± 1.1초 | 19.0초 | 196.5초 |

- 정류장 버스를 본 Episode에서 옆 차로로 추월한 비율: 크리스마스 15/27, 버스 3배 104/133.
- 경로 이탈은 출구 차로(S2 0번)에 못 들어가 다른 길로 빠진 경우다. 충돌은 아니다.

같은 공식 시드에서 추월을 모르는 1단계 BC(dag3)와 비교하면 (결과: `official_eval/baseline_dag3/`):

| 조건 | 복잡 구간 평균 (dag3 → v3_3) | 버스를 만난 Episode (dag3 → v3_3) |
|---|---|---|
| 평시 | 15.6 → 15.2초 | 25.3 → 16.1초 (11회) |
| 크리스마스 | 22.6 → 21.3초 | 37.7 → 26.0초 (27회) |
| 크리스마스 + 버스 3배 | 30.0 → 22.7초 | 39.9 → 24.3초 (131회) |

- 버스를 만나는 Episode가 평시 4%, 크리스마스 9%뿐이라 전체 평균의 단축 폭은 작다. 버스를 만났을 때 10초 안팎이 줄어든다.
- 추월 방식: 버스가 없으면 출구 때문에 맨 오른쪽(정류장 차로)으로 가지만, 관측 [36]이 켜지면 합류점 앞에서 왼쪽으로 한 칸 옮겨 정류장 옆 차로로 지나간 뒤 S2에서 맨 오른쪽으로 돌아간다 (학습 과정 기록 11.4절).
- 그래프 `official_compare.png`, 영상 `video/bus_overtake_compare.mp4`

### 2.2 검증용 시드에서 이전 모델과 비교 (조건마다 300 Episode)

| 조건 | 충돌 (dag3 → v3_3) | 복잡 구간 (dag3 → v3_3) |
|---|---|---|
| 평시 | 0% → 0% | 16.0 → 15.2초 |
| 크리스마스 | 0.3% → 0% | 21.9 → 20.5초 |
| 크리스마스 + 교통량 1.3배 | 0.3% → 0% | 25.3 → 23.4초 |
| 크리스마스 + 버스 3배 | 1.3% → 0.7% | 31.7 → 22.6초 |

- 크리스마스에서 버스를 만난 Episode만 보면 36.2초 → **22.9초**다.
- 학습 시드를 바꿔 3번 학습해 봤다. 시간은 같고, 충돌은 0~1.3%로 흔들린다.

## 3. 데이터 수집 명령

```bash
conda activate sumo-rl
python collect_pomdp_data.py --model models/bc_v3_3.pt --episodes 1000 --workers 8 --seed 100 --name final_normal
python collect_pomdp_data.py --model models/bc_v3_3.pt --episodes 1000 --workers 8 --seed 200 --christmas --name final_xmas
```

- `--model`만 주면 PPO 형식으로 자동 판별한다. 결정적 행동이 기본이고, 다양성이 필요하면 `--stochastic`을 쓴다.
- **`--seed`는 100 이상을 쓸 것.** 학습 데이터는 11~93을 썼다.
- 속도 (맥북, 8개 병렬): 평시 약 210 step/s, 크리스마스 약 150 step/s. 1 Episode는 약 370~400 step이다.
  - 10^7 step이면 평시만 약 13시간, 크리스마스만 약 19시간 걸린다.
  - "10^7 데이터"의 단위는 조교에게 확인할 것.

## 4. 학습 방법 요약

1. **규칙 기반 운전자(선생)**, `utils/rule_policy.py`
   - IDM 가감속
   - 경로상 필요할 때만 차선 변경 (틈 수락), SUMO 차선변경 안전판정으로 확인
   - 막히면 5 m/s로 감속해 기다림
   - 정류장에 버스가 서 있으면 옆 차로로 추월
2. **시연:** 평시 400 + 크리스마스 400 + 크리스마스·버스 3배 200 Episode
3. **BC:** PPO 네트워크를 시연에 지도학습 → **DAgger 3라운드** (학생이 운전한 상태에 선생의 정답을 붙여 추가)
4. **PPO 미세조정(시간 단축):** 10가지 가까이 시도했지만 BC보다 유의하게 빠르지 않았고, 과감하게 하면 충돌이 늘었다. 추월을 모르는 BC에서 PPO가 추월을 스스로 찾는지도 실험했지만 찾지 못했다. 그래서 최종 모델은 3번의 결과다.
   - 이유 (학습 과정 기록 11.5절): 줄일 수 있는 시간이 버스를 만난 드문 Episode에만 있고(크리스마스 9%), 그 1~2초 차이가 교통 운에 묻히며, 시간을 줄이는 추월은 여러 단계 행동이라 무작위 탐험으로 찾기 어렵다. 탐험하면 충돌이 늘고, BC에 묶어 두면 행동이 안 바뀐다.

다시 만들기: `bash scripts/training/train_final_model.sh`

## 5. 반드시 공개할 것

- 시연자(규칙)는 SUMO 내부 정보를 쓴다. 최종 모델은 관측만 본다.
- 관측 33 → 37차원 (팀 합의 필요):
  - [33]·[34] 옆 차로 막힘 (사각지대 경고, SUMO 판정 포함)
  - [35] 경로상 옮길 차로 수 (내비 차로 안내)
  - [36] 80 m 안 정류장 버스 정차 (카메라)
- 시간 단축은 RL이 아니라 "관측 추가 + 버스 추월을 시연으로 가르친 BC"의 결과다.
- 신호 정지는 SUMO 안전 모드(speedMode 24)가 담당한다.
- 크리스마스·버스 3배 조건은 학습에도 썼다. 처음 보는 조건은 크리스마스 ×1.3이다.
- 수업 코드 수정:
  - 충돌을 도착으로 세던 버그
  - 시간초과 처리
  - 시간 벌점
  - 평가 시드 분리 (`--eval-seed`)
